## Method

- **v3** — `UniswapV3Factory.getPool(token, quote, fee)` for fee tiers 100/500/3000/10000 against USDG and WETH.
- **v4** — poolId derived as `keccak256(abi.encode(currency0, currency1, fee, tickSpacing, hooks=0))`,
  then probed through `StateView`. Existence is `slot0.sqrtPriceX96 != 0`, **not** `getLiquidity != 0`:
  `getLiquidity` returns only active in-range liquidity, and at least one live pool (SPY 500/10) is
  initialised with zero active liquidity. Hook pools are **not** discoverable this way — see Limitations.
- **Rialto** — propAMM pairs probed with `getAmountOut(bool,uint256)` at rising sizes. A `0` return is the
  maker declining that size, per the Rialto spec; it is recorded as a cap, never as an error.

## Limitations

- Hook pools (v4 pools with a non-zero `hooks` address) are **not** enumerated. poolId derivation needs the
  hook address as an input, so they cannot be brute-forced, and both public 4663 RPCs refuse `eth_getLogs`.
  Any hook pool must be added to the registry by address. This is an honest gap in coverage, not a claim of none.
- Uniswap v2 is deployed on 4663 (`UniswapV2Factory`) but is not swept here.
- `active` is a snapshot of in-range liquidity at one block and moves constantly.
